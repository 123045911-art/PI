4. ERRORES Y ADVERTENCIAS DETECTADOS (AVISOS Y RIESGOS)
-------------------------------------------------------------------------------
[AVISO 1 - RIESGO DE FALLO DE ARRANQUE EN ENTORNOS SIN CÁMARA]
- Ubicación: Servicio `flask_service` -> `devices: - "${CAMERA_DEVICE:-/dev/video0}:/dev/video0"`
- Detalle: Si se ejecuta `docker compose up` en un servidor VPS/Cloud, WSL2, o en una PC
  sin una cámara web USB conectada en `/dev/video0`, Docker fallará inmediatamente al levantar
  el contenedor con el siguiente error:
  "error gathering device information: unable to stat /dev/video0: no such file or directory"
- Solución recomendada: Para entornos sin webcam física, comentar la sección `devices:` o utilizar
  un contenedor dummy / fuente de stream por red.

[AVISO 2 - ESTADO DEL DEMONIO DE DOCKER EN EL ANFITRIÓN]
- Ubicación: Entorno local / Sistema operativo
- Detalle: Al ejecutar `docker compose ps` o `docker info`, se detectó que el servicio
  de Docker (`docker.service`) no estaba activo en el sistema anfitrión:
  "Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?"
- Solución recomendada: Iniciar el servicio con `sudo systemctl start docker`.

[AVISO 3 - INCONSISTENCIA DE CONFIGURACIÓN DE URL API INTERNA]
- Ubicación: Servicio `laravel` -> `INTERNAL_API_URL=http://api:8000` vs `contador_dashboard/config/services.php`
- Detalle: En docker-compose.yml la variable apunta a `http://api:8000`, pero en el archivo
  `config/services.php` el valor por defecto incluye el sufijo `/api/v1` (`http://fastapi:8000/api/v1`).
  Si en algún archivo de controlador se concatena `/api/v1` nuevamente, las peticiones hacia
  FastAPI devolverán HTTP 404 o 500.

[AVISO 4 - VOLUMEN ANÓNIMO EN LARAVEL VENDOR]
- Ubicación: Servicio `laravel` -> `volumes: - /var/www/html/vendor`
- Detalle: El volumen anónimo preserva la carpeta vendor del contenedor, pero si se realizan
  cambios en `composer.json` en el host, la carpeta `vendor` interna no se actualizará automáticamente
  a menos que se ejecute `composer install` dentro del contenedor o se regenere el volumen.


5. RECOMENDACIONES DE MEJORA
-------------------------------------------------------------------------------
1. En entornos de producción o servidores sin cámara web, hacer que la sección `devices` en
   `flask_service` sea condicional o asignarle un flag en `.env` para evitar errores de montaje.
2. Asegurar que las variables de contraseña en `.env` sean cambiadas antes de desplegar en producción.
3. Asegurar que el servicio Docker esté iniciado con `sudo systemctl start docker` antes de ejecutar `docker compose up --build`.
